Building Real-Time Tile Pipelines with MapLibre GL

Most WebGIS tutorials assume your data is static — a shapefile you convert once and serve forever. Real deployments rarely work that way. Vehicle positions, sensor readings, and live weather layers change every few seconds, and your tile pipeline has to keep up without falling over.

The problem with static tiles

Pre-rendered vector tiles are fast, but regenerating a full tile set on every update is wasteful when only a handful of features actually moved. The fix is to separate slow-changing basemap layers from fast-changing live layers, and stream only the latter.

Architecture

A minimal setup looks like this: a PostGIS table holding live positions, a lightweight Node service that queries it and emits GeoJSON deltas, and a MapLibre GL source updated in place rather than reloaded.

map.getSource('live-vehicles').setData(geojson);

Calling setData on an existing GeoJSON source is far cheaper than tearing down and re-adding a layer — MapLibre diffs the feature set internally.

Keeping it smooth

Throttle updates to match your actual data cadence — polling every 500ms for data that changes every 5 seconds just burns battery on mobile clients. Pair the live layer with a subtle CSS transition on marker position so movement reads as motion rather than teleportation.
